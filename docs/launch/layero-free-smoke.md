# RE — Layero Free: инфраструктурный smoke test

Дата подготовки: 12 октября 2026.

14 октября 2026 владелец разрешил один тестовый проект `re-layero-free-smoke`
и один CLI-деплой только этой тестовой папки. В последующем сообщении владелец
снял предварительную проверку тарифа, trial Pro и карты и разрешил использовать
CLI с существующей авторизацией при недоступности MCP. Это условие больше
не блокирует работу. Оплата, изменение тарифа, платные ресурсы и ввод
платёжных данных по-прежнему запрещены.

## Согласование одного деплоя

MCP не загружает Node-исходники из локальной папки. Предложение:
создать один отдельный проект через MCP, загрузить только infra/layero-smoke
через CLI, проверить результат через MCP и HTTPS. GitHub не подключать,
git push не выполнять. Не использовать Pro, базы, платные услуги или секреты.
Разрешение получено 14 октября 2026 в указанном объёме; повторное разрешение
на этот же объём не требуется. Предварительная проверка тарифа отменена.
При недоступности MCP разрешён один деплой через CLI с существующей
авторизацией, создающий ровно один тестовый проект. Дополнительные проекты,
повторные деплои и миграция RE требуют отдельного согласования.

## Что записать после разрешения

- Идентификатор проекта, точный HTTPS-адрес; тариф по решению владельца не проверяется.
- Идентификатор деплоя, фактическая версия Node, HTTP-статус и реальный JSON health.
- Времена UTC baseline/после простоя, задержки, instanceId/startedAt/uptimeMs/sequence/responseId.
- Длительность простоя без запросов и основание вывода о cold start/разморозке.
- Для каждой фиксированной SMTP-цели: DNS/TCP/TLS/220, этап ошибки,
  безопасный код ошибки, elapsedMs, cached и checkedAt.
- Вывод отдельно о сетевой доступности, авторизации/доставке и надёжности заявок.

## Уже известные ограничения

Постоянного диска у runtime нет; память не переживает остановку и не общая
между инстансами. Поэтому PHP-квитанции на 24 часа и атомарный rate limit
нельзя перенести с прежними гарантиями без постоянного общего хранилища.
При потерянном HTTP-ответе после принятия SMTP возможен дубль после рестарта.
Ненадёжный локальный файл не решает это ограничение.

Free пригоден для проверки транспорта; production-миграция пока не одобрена.
Для надёжности, эквивалентной нынешнему backend, без внешнего хранилища
рекомендовать [готовый Beget-пакет](../beget-deploy.md).
Бесплатность уже существующего Beget-хостинга этим исследованием не подтверждается.

Свой домен, индексация и удаление плашки Layero требуют Pro.
Квоты на [странице потребления](https://docs.layero.ru/billing/usage/) при свежем
чтении 12.10.2026 помечены черновиком и пока не применяются; прежний ответ
в чате о действующих жёстких квотах нужно считать уточнённым.
