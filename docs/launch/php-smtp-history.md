## Backend и пакет

- JSON POST `/api/lead.php`, до 4096 байт; strict boolean consent, participant/partner,
  Unicode-имя до 120 символов, телефон 7–15 цифр или Telegram, контакт до 160 символов.
- Same-origin/HTTPS, без CORS и без доверия произвольным proxy-заголовкам.
- Пять валидных новых запросов с IP за 10 минут по умолчанию, настройка лимита;
  HMAC-ключи вместо исходных IP/имён/контактов, flock и ограниченный размер state.
- UUID запроса остаётся тем же при повторе неизменённых данных. Квитанция SMTP
  предотвращает повтор того же запроса с того же IP в течение 24 часов;
  pending/uncertain блокируют небезопасную повторную отправку.
- PHPMailer v7.1.1 закреплён по commit и SHA-256, с лицензией. Прямое подключение
  официальных исходников; Composer на виртуальном хостинге не требуется.
- SMTP с аутентификацией и TLS, без debug; fixed subject/from/to, plain-text body
  из четырёх полей. Нет SQL, mail() fallback, HTML-писем, передачи партнёрам или
  стороннего обработчика. Положительный результат — принятие SMTP, не доставка.
- Bootstrap, зависимости и runtime проверяют расположение вне public_html.
  Секретный config не создан и исключён из Git/пакета. Диагностика/API не выводят
  PHP trace, SMTP ErrorInfo, адреса и пароли конфигурации.
- `npm run prepare:beget` создаёт отдельные public_html и private/recase-server.
  Обычный dist остаётся preview с выключенным API. GitHub workflow не изменён.

## Выполненные проверки

Нативного PHP/Composer на компьютере нет. Запущен настоящий интерпретатор
PHP 8.3.33 WebAssembly через официальные тестовые пакеты WordPress Playground
в /tmp и Node 24. Этот runtime не используется в production.

`tests/lead-test.php`: **72 проверки** пройдены, PHP syntax проверен для всех
собственных PHP-файлов. Проверены обязательность/формат/длина полей, разные
контакты и типы, CRLF/HTML-вставки, JSON/type/Origin/HTTPS/size, отсутствие согласия,
rate limit/истечение, идентичные и изменённые повторы, pending, SMTP false/exception,
занятый/повреждённый state, отсутствие сырых данных, конфигурация PHPMailer и MIME
через preSend. SMTP не вызывался: транспорт тестов — контролируемая функция.
Для нативного PHP после установки зависимости: `npm run test:php`.

Публичный bootstrap дополнительно исполнен как PHP CGI в том же runtime:
**8 сценариев** с ожидаемыми JSON/HTTP 405, 400, 422, 403, 413, 415, 503.
Проверены заголовки JSON, отсутствие диагностики и отказ при приватном каталоге
внутри document root. Результаты: [php-bootstrap-qa.json](php-bootstrap-qa.json).

Сборки `npm run build` и `npm run prepare:beget` выполнены. Проверены три HTML
страницы в dist и Beget, API только в Beget public_html, vendor SHA-256, отсутствие
config.php/тестов/записей state в release. Текстовые файлы, включаемые в Git,
проверены на приватные ключи, реальные literal-password и приватные конфигурации;
совпадений не найдено. Это проверка текущего набора файлов, не аудит истории Git.
[package-checks.json](package-checks.json).

Обе юридические страницы и оба попапа проверены на **1512×982, 744×1133,
390×844**: состав полей, unchecked required consent, ссылки, отсутствие overflow,
недоступность статического preview. [preview-qa.json](preview-qa.json).
Нативная required-валидация действительно остановила отправку без согласия.

Beget frontend отдельно проверен с localhost mock API, принимающим только
синтетическое имя «Тестовый QA» и тестовые контакты. На всех трёх ширинах

При ошибке восстановлены редактирование и фокус. Значения сохранены.
[mock-api-qa.json](mock-api-qa.json).

Двойной клик по submit при задержанном ответе создал **один** запрос в mock API
(счётчик 13 → 14). [double-click-qa.json](double-click-qa.json).
Клавиатура и короткий экран 390×500 проверены отдельно: поверхность прокручивается,
