# RE — отдельный Layero Free smoke test

Только инфраструктурная диагностика. Это не API заявок и не миграция RE.
Никаких npm-зависимостей, SMTP-паролей, имён, контактов или отправки писем.
Деплой разрешён только после явного подтверждения владельца.

## HTTPS-расширение, 14 октября 2026

Добавлен `POST /api/https-probe`: пустое тело и `X-Smoke-Probe: https-only`.
Два фиксированных GET-адреса: example.com и документированный API Postbox
`https://postbox.cloud.yandex.net/v2/email/configuration-sets`, без авторизации.
Никакой отправки писем, произвольных URL, редиректов, ключей, тел ответа или
чувствительных заголовков в диагностике. DNS/TCP/TLS/HTTP и времена разделены;
12 секунд на цель. 401/403 означает доступность транспорта, не авторизацию.

На Node 22.23.3 пройдены 17 локальных тестов, включая регрессию SMTP/health.
Для запуска: `node --test https-probe.test.mjs smtp-regression.test.mjs`
из этой папки с Node 22. Тестовые TLS-ключи создаются только в tmp и удаляются.

Существующий проект уже создан владельцем. Разрешён только один дополнительный
деплой в него; он завершился fetch failed до упаковки/загрузки. Повтор агентом
не выполняется. [Результаты, ограничения Postbox и команды для Mac](https-smoke-report.md).
Ни один облачный HTTP-статус новой HTTPS-пробы пока не подтверждён.

## Приложение

- Node.js 22, стандартные библиотеки. `npm start` запускает `server.mjs`.
- Слушает `0.0.0.0` и `process.env.PORT` (локально по умолчанию 3000).
- `GET /` и `GET /api/health`: JSON с instanceId, startedAt, uptimeMs,
  sequence и случайным responseId. `Cache-Control: no-store`.
- `POST /api/smtp-probe`: только пустой запрос с заголовком
  `X-Smoke-Probe: tcp-tls-only`. Параметры URL и тело запрещены, CORS отсутствует.
- Только четыре фиксированные цели: smtp.beget.com и smtp.yandex.ru, порты 465/587.
- На 465: TCP → TLS с проверкой сертификата/имени → приветствие SMTP 220.
- На 587: TCP → 220 → `EHLO smoke.invalid` → проверка STARTTLS →
  `STARTTLS` → TLS с проверкой сертификата/имени.
- Никогда не посылает AUTH, MAIL FROM, RCPT TO или DATA. После проверки соединение закрывается.
- Каждый сеанс ограничен 8 секундами целиком, все четыре идут последовательно:
  не более ~32 секунд работы, плюс холодный запуск и передача HTTP.
- Один пакет диагностики на процесс, результаты повторных вызовов кешируются.
  Параллельный вызов возвращает 429. После перезапуска лимит обнуляется;
  это временная защита теста, не гарантия idempotency production API.
- Результаты содержат этап, булевы признаки, длительность, TLS-протокол и
  безопасный код ошибки. Нет IP сервера, полных SMTP-ответов, сертификатов,
  HTTP-тел, секретов или логирования входящих запросов.
- Верхнее `ok: true` у HTTP-отчёта означает, что диагностика выполнена;
  успешность соединения определяется `results[].ok`.

[Beget документирует порт 465](https://beget.com/ru/kb/how-to/mail/obshhie-svedeniya).
587 на Beget — дополнительная проверка, не документированный в этой инструкции порт.
Его отказ не доказывает блокировку Layero.
[Яндекс документирует 465 и 587](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).
Проверка этих хостов не означает выбор почтового провайдера для RE.

## Локальная проверка

Из корня RE: `node --test tests/layero-smoke.test.mjs`.
Тесты используют только 127.0.0.1; временный самоподписанный сертификат/ключ
создаётся в системном tmp и удаляется. Доверие этому сертификату инжектируется
только в тестах; production всегда проверяет общедоверенный TLS-сертификат.

`layero.json` содержит только `runtime: node_web`: у этого приложения нет
известного серверного фреймворка, его нельзя публиковать как статику.
Команда старта и версия Node берутся из package.json. Полный RE не загружается.

## Путь публикации — пока НЕ выполнен

Актуальный [MCP](https://docs.layero.ru/agents/mcp-tools/) предоставляет:

1. `project_create`: пустой проект; сам по себе runtime не публикует.
2. `import_repo`: импорт существующего удалённого репозитория, по умолчанию
   сразу запускает сборку. Новых локальных файлов на GitHub пока нет,
   git push запрещён, поэтому этот путь не подходит.
3. `publish_site`: только готовая статика, Node-исходники не собирает.

Разрешённый путь: создать ровно один проект `re-layero-free-smoke` через MCP
и загрузить только эту папку CLI с явным `--project` из ответа MCP.
Если MCP недоступен, владелец разрешил один CLI-деплой этой папки с созданием
одного тестового проекта и использованием существующей авторизации.
Без GitHub и git push. Проверка тарифа перед созданием отменена владельцем.
CLI может потребовать отдельную авторизацию: доступ MCP не доказывает наличие
CLI-сессии. Не передавать токены в чат, Git или layero.json.

Перед облачными действиями должен успешно пройти локальный dry-run:

```sh
# Только из infra/layero-smoke; не создаёт проект и не загружает код.
npx layero@latest deploy --dry-run --json
```

Тариф, trial Pro и наличие карты по последнему указанию владельца не проверять.
Не включать trial Pro, подписку, базу данных, свой домен, аналитику,
платные логи/аудит или оплату превышения; не вводить платёжные данные.
Не выдавать непроверенный тариф за подтверждённый Free. При требовании оплаты
или технической ошибке остановиться. Повторный деплой требует согласования.

## План проверки после одного деплоя

1. Использовать точный HTTPS-адрес ответа CLI, не составлять его из имени.
2. Проверить `site_status(path="/api/health")`: ответ самого сайта, не заглушка
   платформы/SPA-fallback. Затем прочитать JSON и измерить задержку HTTPS-запроса.
3. Сделать две health-проверки для baseline: новый responseId/sequence,
   стабильный instanceId и растущий uptime. Записать UTC-время и задержки.
4. Прекратить любые обращения, включая открытый браузер/мониторинг, на 10 минут.
   Затем повторить health. Время ожидания само по себе не доказывает cold start.
   Новый instanceId, новое startedAt и небольшой uptime подтверждают новый
   процесс после простоя; при нескольких инстансах дополнительно проверить
   стабильность идентификатора повторным запросом. Старый instanceId означает,
   что новый процесс не доказан: это может быть разморозка. Строгое доказательство
   удаления прежнего контейнера требует сигнала платформы; при его отсутствии
   отметить это ограничение, не подменять результат задержкой.
5. Выполнить один явный POST smtp-probe с пустым телом и указанным заголовком.
   Сохранить каждый результат, включая отказ и его этап. `cached: true` означает
   прежний результат, не повторное сетевое измерение.
6. Успешный TCP без TLS не достаточен; успешный TCP/TLS/220 доказывает только
   соединение с выбранным сервером. Авторизация и доставка ещё не проверены.
7. Зафиксировать результаты в docs/launch/layero-free-smoke.md. Не добавлять
   автоматический повторный деплой. При ошибке сначала диагностика; одинаковая
   ошибка дважды — остановка, без третьего деплоя.

## Граница решения о миграции

Даже положительный сетевой тест не доказывает надёжность API заявок.
У [runtime нет постоянного диска](https://docs.layero.ru/runtime/stateless/).
Память теряется при остановке, а отдельные инстансы не разделяют её.
Постоянный rate limiting и квитанции pending/accepted/uncertain на 24 часа
невозможно сохранить эквивалентно PHP-файлу на Beget одной памятью процесса.

Без постоянного хранилища возможна лишь защита в пределах одного живого
процесса. После рестарта/между инстансами остаётся риск повторного письма и
сброса лимитов, особенно если SMTP принял письмо, а HTTP-ответ потерялся.
Не использовать локальный файл/SQLite как постоянное хранилище и не обещать
exactly-once отправку. Краткая пауза ~20 секунд — это заморозка, а не гарантия
сохранности процесса навсегда. Фоновый cron тоже не надёжен при сне.

Если сохранение существующей защиты обязательно и внешнее постоянное
хранилище исключено, рекомендовать готовый Beget-пакет. Не начинать перенос
PHP на Node до облачных результатов и согласования этой границы.

[Жизненный цикл](https://docs.layero.ru/runtime/lifecycle/): Free 256 MB / 0,25 vCPU,
HTTP-запрос до 60 секунд, холодный запуск может занимать секунды.
[Fullstack](https://docs.layero.ru/deploys/layero-json/): frontend/backend и apiPrefix
поддерживаются, но не нужны для проверки одного минимального runtime.
[Тарифы](https://docs.layero.ru/billing/plans/): свой домен, индексация и удаление
плашки требуют Pro. Плашка означает, что точная визуальная идентичность
публичного RE на Free не гарантируется даже при неизменном frontend.
[Сетка потребления](https://docs.layero.ru/billing/usage/) на 12.10.2026 помечена
«Черновик»: перечисленные квоты/цены превышения пока не действуют. Не считать
их действующими гарантиями или включать платные функции для теста.
